Language Rules and Conventions

This page is the reference for PE3 to the final interpreter. If another page seems to disagree with it, this page is correct. The conventions here will not change while you are working.

← Overview

Language

RuleRequirement
ProgramOne or more output statements
Output statementThe output keyword followed by an expression. It produces one integer result.
ExpressionAn integer literal, or an operation on two expressions. Operations can be nested.
OperationsAddition, subtraction, multiplication and division. Each takes exactly two operands.
Integer literalsOne or more digits (0 to 9). Leading zeros are allowed. There are no negative literals, but results can be negative.
DivisionInteger division that truncates toward zero. (0 - 7) / 2 is -3.
Division by zeroAn evaluation error
Not supportedVariables, assignments, functions, strings, comments, other operators

Layout

RuleRequirement
StatementsOne per line, in both terminator modes. A statement cannot span lines.
Newline modeThe line break ends the statement. The line break after the last statement is optional.
Semicolon modeEvery statement ends with ; before the line break. The line break after the last statement is optional.
BoundariesIf enabled, the start keyword is the first line and the end keyword is the last. Each is alone on its line and takes no semicolon.
Blank linesIgnored. They produce no NEWLINE token, in both terminator modes.
Spaces and tabsOptional between tokens, wherever the tokens stay distinct. Prefix notation needs spaces between operands: (SUM 2 3).
Line endings\n, \r\n and \r each count as one line break

Tokens

The lexer returns a list of (type, lexeme) tuples. Types are fixed. The lexeme is the exact text from the source.

TypeWhen it appears
PRINTThe output keyword
ADD, SUB, MUL, DIVThe keyword for that operation
INTEGER_LITERALA run of digits
LEFT_PAREN, RIGHT_PAREN( and )
COMMA,, in function-like notation only
SEMICOLON;, in semicolon mode only
NEWLINEA line break after a line with content. The lexeme is \n, even for \r\n or \r. Blank lines and a break at the start of a program produce none, so consecutive breaks produce one. A last line without a break produces none. In semicolon mode, the token comes after the SEMICOLON token.
START, ENDThe boundary keywords, only when enabled

A word starts with an English letter and continues with letters, digits or underscores. The whole word is read, then compared with the keywords. If case_sensitive is false, the comparison ignores case. A word that is not a keyword is an error. Any character that is not part of the language is an error, including ., +, -, and letters outside English. A comma is valid only in function-like notation and a semicolon only in semicolon mode.

Grammar

program   ::= [START NEWLINE] statement+ [END [NEWLINE]]       (START and END only if boundaries are on)
statement ::= PRINT expr [SEMICOLON] (NEWLINE | end of input)    (SEMICOLON only in semicolon mode)

function-like:   expr ::= INTEGER_LITERAL | OP LEFT_PAREN expr COMMA expr RIGHT_PAREN
prefix:          expr ::= INTEGER_LITERAL | LEFT_PAREN OP expr expr RIGHT_PAREN

OP ::= ADD | SUB | MUL | DIV

Syntax Tree

NodeShape
Program("PROGRAM", [statement, ...])
Output statement("PRINT", expression)
Integer("INTEGER", 2), with a Python int
Operation("ADD", left, right), and likewise SUB, MUL, DIV

Errors

ProblemReported byException
Invalid character or word, such as @ or an unknown wordLexerValueError("Invalid token")
Structure that does not follow the grammar, such as a missing operandParserSyntaxError("Invalid syntax")
Division by zeroEvaluatorZeroDivisionError("Division by zero")

If an output statement fails, the whole call raises the error and returns no results. The messages must match exactly.

Differences From PE2

PE2's tokenize(source) works on a fixed language and reports an invalid character as an ("ERROR", text) token. The PE4 lexer works on your language and raises ValueError instead, so the three stages report problems in the same way. The shared token types (INTEGER_LITERAL, LEFT_PAREN, RIGHT_PAREN) have the same names in both.
