Lexer and Parser

Write a lexer and a parser for the language you designed in PE3. The lexer turns a program into tokens, and the parser turns the tokens into a tree. This is the longest exercise, so start early.

Functions

# lexer.py
def tokenize(source, spec):
    ...   # returns a list of (type, lexeme) tuples

# parser.py
def parse(tokens, spec):
    ...   # returns an AST

source is the program as a string. spec is your language.json, loaded as a Python dictionary. Do not read files or print anything in either function.

Rules

Follow the token types, grammar and tree shapes on the Language Rules and Conventions page. They are the same for every student.

  • Lexer: skip spaces and tabs. Return one NEWLINE token for each line break that ends a line with content, and none for blank lines. The Language Rules and Conventions page gives the details.
  • Lexer: read a word as a letter followed by letters, digits or underscores. If it is not one of your keywords, raise ValueError("Invalid token"). Raise the same error for any other unknown character.
  • Lexer: keep the lexeme exactly as typed, even when your language is case-insensitive.
  • Parser: use only token types, not keywords.
  • Parser: accept one statement per line, in both terminator modes. Treat a program with no output statement as a syntax error.
  • Parser: if the tokens do not follow the grammar, raise SyntaxError("Invalid syntax").

Example

For the Calcora statement SHOW SUM(2, 3), the lexer returns:

[('PRINT', 'SHOW'), ('ADD', 'SUM'), ('LEFT_PAREN', '('),
 ('INTEGER_LITERAL', '2'), ('COMMA', ','), ('INTEGER_LITERAL', '3'),
 ('RIGHT_PAREN', ')')]

and the parser returns:

("PROGRAM", [("PRINT", ("ADD", ("INTEGER", 2), ("INTEGER", 3)))])

Testing

Download selftest.py, put it in the same folder as your files (with their original names), and run:

python selftest.py pe4

It generates programs from your language.json and compares your results with the expected ones. I will run the same kinds of tests, plus invalid programs for the parser, which the self-test does not include. Write a few of your own, such as a missing operand or a missing closing parenthesis. Your parser is tested with correct tokens, so a lexer mistake does not cost you parser points.
