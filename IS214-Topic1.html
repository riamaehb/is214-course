Programming languages are not merely different ways of writing the same instructions. They embody different ways of expressing computation.

In this topic, we establish the basic vocabulary needed for the rest of IS 214: what a programming language is, why languages differ, how they can be classified, how programs are executed, and how language design involves trade-offs.

Python will be our primary language throughout the course.

By the end of this topic, you should be able to

  1. Explain what a programming language is in terms of syntax, semantics, and computation.
  2. Explain why programming languages have evolved and why different languages are designed for different purposes.
  3. Classify programming languages according to abstraction level, programming paradigm, application domain, and implementation approach.
  4. Distinguish imperative and declarative programming and recognize common paradigms within each.
  5. Explain the basic difference between compilation and interpretation.
  6. Describe the major phases involved in translating a program, from source code to executable form.
  7. Evaluate programming languages using criteria such as readability, writability, reliability, and cost.

What Is a Programming Language?

What exactly is a programming language? You probably already have an intuitive answer: "It's a language that lets us tell a computer what to do." That's not wrong, but it is incomplete.

A programming language provides a formal way to describe computation. It defines what can be written, how those elements can be combined, and what those constructions mean when executed.

One Computation, Many Languages

Here's the same computation — print "Hello, World!" — written four different ways.

Assembly

Low-level, explicit interaction with machine-oriented operations.

mov ah, 9
mov dx, offset msg
int 21h

Java

Object-oriented and strongly structured.

public class Hello {
  public static void main(String[] a) {
    System.out.println("Hello, World!");
  }
}

Scheme

Functional style.

(define (hello)
  (display "Hello, World!"))

Python

Compact, high-level syntax.

print("Hello, World!")
All four programs produce essentially the same observable result. Why do they look so different?

This is our first major conceptual question. The answer leads directly into: programming languages make different design choices about how computation is expressed.

Why Study Programming Languages?

You don't study programming languages because you need to memorize twenty languages. You study them because understanding languages helps you:

  • recognize patterns across languages;
  • choose appropriate languages for particular problems;
  • learn unfamiliar languages more quickly;
  • understand why certain constructs behave the way they do; and
  • write better programs.

Why Are There So Many Programming Languages?

A language exists because someone made choices. For example:

  • Should memory management be explicit?
  • Should variables have fixed types?
  • Should programs describe how to solve a problem, or what result is wanted?
  • Should functions be ordinary values?
  • Should objects be central to the language?
  • Should the language prioritize safety, performance, simplicity, or programmer productivity?

There is no single programming language that is best for every purpose.

Programming-language design is therefore a collection of trade-offs.

Programming Paradigms

A programming paradigm is a way of thinking about and organizing computation. Instead of asking "what syntax does this language use?" we ask: "what model of computation does this language encourage me to use?"

Imperative programming

Emphasizes how a computation is performed — a program describes a sequence of actions that changes program state.

total = 0
for x in numbers:
    total = total + x

Notice what the program tells us: create total; iterate over numbers; take the current value; add it to total; update total. This is an imperative description of the computation.

Check 2

Declarative programming

Emphasizes what result or relationship is wanted, rather than specifying every step. For example, SQL:

SELECT name
FROM students
WHERE grade >= 1.5;

We don't tell the database to scan this disk block, then compare this row, then move to the next row. We describe what data we want.

Python Is Not "An Object-Oriented Language"

Consider:

total = 0
for x in numbers:
    total += x

versus:

total = sum(numbers)

Both are Python. The first emphasizes explicit state changes and iteration. The second uses a higher-level abstraction.

Now consider:

students = [
    {"name": "Ana", "grade": 1.25},
    {"name": "Ben", "grade": 1.75}
]
top_students = list(
    filter(lambda s: s["grade"] <= 1.5, students)
)

This uses a more functional style.

A programming language can support multiple paradigms. A program can also use multiple paradigms.

This will matter later when we discuss Python's design.

Classifying Programming Languages

There isn't just one way to classify a programming language. We can classify languages according to:

1. Abstraction level

Low-level (machine language, assembly) vs. high-level (C, Java, Python) — the key difference is how much of the underlying machine the programmer has to deal with.

2. Paradigm

Imperative, object-oriented, functional, logic, etc.

3. Application domain

Scientific, business, AI, systems, scripting, and special-purpose languages.

4. Implementation approach

Compiled, interpreted, or combinations of the two.

These classifications describe different dimensions.

Python can simultaneously be high-level + multi-paradigm + general-purpose + interpreted/bytecode-based. That's much more useful than memorizing a single category.

How Do We Judge a Programming Language?

  • Readability — how easily can humans understand programs written in the language?
  • Writability — how easily can programmers express solutions?
  • Reliability — how likely is the language to help programmers produce programs that behave correctly?
  • Cost — what does it cost to learn, develop, execute, maintain, and support programs written in the language?

These expand into design factors: simplicity, orthogonality, abstraction, expressivity, type checking, exception handling, and implementation/tool support.

Embedded thought question

Is the most writable language necessarily the best language?

No. Giving programmers many different ways to express the same operation may make a language powerful — but also harder to learn, read, and maintain. This introduces the idea of trade-offs directly: increasing writability can come at the cost of readability.
Check 5 · reflection
Why might a language designer deliberately choose a more verbose syntax?
Readability, explicitness, reliability, maintainability, reduced ambiguity.

Each phase takes the previous phase's output and transforms it into something more meaningful: characters become tokens, tokens become a tree, and a checked, meaningful structure eventually becomes code that runs.

A program is not magically "run." A language implementation has to determine what the source code means and how to execute that meaning.

Errors Have a Location

Lexical error

x = 10 @ 5

Suppose @ isn't a valid token in our language. The problem: the characters cannot be converted into valid tokens.

Syntax error

if x > 10
print(x)

The tokens exist, but their arrangement violates the grammar.

Semantic error

x = "hello"
y = x + 5

The structure may be syntactically valid, but the operation may not have the required meaning.

The Big Picture

We started with: what is a programming language? Now you should have a richer answer.

A programming language defines a way of expressing computation through syntax + semantics + execution mechanisms. Different languages make different choices about abstraction, paradigm, syntax, types, control, execution, safety, performance, and programmer productivity — and language implementations translate those abstractions into executable behavior.

Topic 1 Summary

Remember these ideas

  1. A programming language provides a formal way to describe computation.
  2. Syntax determines what programs are structurally valid.
  3. Semantics determines what valid programs mean.
  4. Programming languages differ because they make different design choices.
  5. Programming paradigms provide different ways of thinking about computation.
  6. Languages can be classified along several dimensions; these classifications are not mutually exclusive.
  7. Programming languages can be evaluated using criteria such as readability, writability, reliability, and cost.
  8. Compilation and interpretation are implementation approaches, and real systems often combine them.
  9. Language implementations analyze programs in stages, including lexical, syntax, and semantic analysis.
  10. The concepts introduced here will be developed throughout the rest of IS 214.
