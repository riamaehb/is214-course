From Language Design to Implementation

Overview of PE3–PE6 and the Interpreter Project

What are we building?

In PE1, you practiced Python programming. In PE2, you implemented a lexer for a calculator language with fixed keywords and lexical rules.

In the remaining exercises, you will design your own small calculator language and implement a program that can read and execute it. Each exercise contributes to the same implementation.

Keep your files and working code. You will extend and improve them rather than start a new project each time.

PE3

Design your language

Use the guided Language Designer to select your language's name, keywords, expression notation, statement terminators, case sensitivity, and optional program boundaries. Explain your choices briefly.

The designer exports your language rules to language.json. Those rules determine which programs your later code must recognize.

Output: validated language.json
PE4

Implement the lexer and parser

Write a lexer that converts your language's source code into tokens. Write a parser that checks the syntax and builds an abstract syntax tree (AST).

Your implementation must recognize the keywords and notation you selected in PE3. It must also reject invalid input using the error rules in the assignment.

Output: source code → tokens → AST
PE5

Implement the evaluator

Use the AST from PE4 to compute arithmetic results. Support addition, subtraction, multiplication, division, and nested expressions.

A program may have multiple output statements. Each output statement produces one result.

Output: AST → results
PE6

Test and debug your interpreter

Create and run test cases for valid programs, nested expressions, multiple output statements, invalid tokens, syntax errors, and evaluation errors. Identify and fix problems in the lexer, parser, and evaluator.

This exercise improves the implementation you already have. You do not need to add another language feature or build a translator.

Output: tested implementation and test cases

How the components fit together

PE3: language rules→PE4: lexer→PE4: parser→PE5: evaluator→PE6: testing

A sample function-like language could contain these statements:

SHOW SUM(2, 3)
SHOW PRODUCT(4, 5)

Its interpreter would produce two results: 5 and 20. Your own keywords and notation will depend on your PE3 choices.

This is an illustration, not a required language design.

Interpreter project: integrate your work

Submit the completed interpreter produced through PE3–PE6. It should load the language specification, recognize source code written in your language, parse valid programs, compute their results, and reject invalid programs appropriately.

The final submission will be assessed using automated tests. There is no live demonstration or video requirement. Detailed function interfaces, test expectations, and submission instructions will be given in the individual activities.

Scope: This is a small arithmetic language. You do not need variables, assignments, user-defined functions, loops, or a translator. Those broader programming-language concepts remain part of the study guides and learning quizzes.

How to approach the remaining work

  • Complete the relevant study guide before starting its associated exercise.
  • Keep a consistent language.json throughout PE4–PE6.
  • Test each component before integrating it with the next one.
  • Follow the detailed specifications in each exercise, including function signatures and submission format.
  • Use the learning quizzes to check your understanding of topics beyond the interpreter's limited scope.

The goal is to understand how the pieces of a programming-language implementation work together, and to build a small version that works correctly.
